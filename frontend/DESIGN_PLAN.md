# 知序前端设计与实施规划

## 产品定位

“知序”是面向选调生信息的研究型检索空间。首页以问题输入为入口，结果页把筛选、记录与洞察放在同一阅读空间，探索页强调专业、地区、岗位之间的关系。参考视频仅作为交互节奏参考；视觉采用暖白网格底、深蓝文字、青蓝与少量靛紫强调，以及带编号和分割线的信息排版。

当前阶段的 React 前端已作为桌面 EXE 的默认界面，**新版中的记录均为匿名 Mock Data**，尚未调用真实数据库或真实 AI 服务。桌面版顶部“本地数据工作台”可进入 `/legacy/`，继续使用现有的真实数据搜索、同步、设置与导出功能。

## 页面与状态

| 页面 | 主要区域 | 核心状态变化 |
| --- | --- | --- |
| 概览 `/` | 左侧介绍与数据概况；右侧 Command Palette 式检索 | 输入时逐步识别届别、专业、地区、类型等条件 |
| 检索 `/search` | 固定筛选栏、时间线式结果、内嵌洞察面板 | 提交问题后先显示约 1.15 秒查询解析；结果按筛选重排；详情从右侧展开 |
| 探索 `/explore` | 可换维度的 Sankey 关系图、届别趋势、地区分布、节点检查器 | 悬停高亮关联，点击节点过滤记录并可进入检索 |

从搜索前到搜索后的路径：`输入 → 条件识别 → 查询解析 → 结果与洞察 → 详情/探索`。结果页顶部 Query Bar 在滚动后压缩并保持可用。筛选栏在桌面端保持固定；手机端改为页面内过滤区。

## 视觉与动效规则

- 背景 `#f7f6f2`；主文字 `#1d3449`；主操作深蓝 `#173d59`；强调青蓝 `#2b7894`，少量靛紫用于次级标签。
- 通过细网格、节点连线、编号、细分隔线建立“知识网络 + 数据探索”识别度，不依赖大面积彩色渐变或大白卡片。
- 页面入场：透明度 + 12px 位移，约 300ms；结果列表逐条延迟 55ms；抽屉采用弹簧位移；图表绘制约 650ms；数字计数约 720ms。
- 尊重系统 `prefers-reduced-motion`。动画只解释状态变化，不作为装饰噪声。

## 组件与数据边界

`Layout`、`Navbar`、`SmartSearch`、`QueryParser`、`FilterPanel`、`ResultList`、`ResultItem`、`DetailDrawer`、`InsightPanel`、`DataExplorer`、`ChartContainer` 分别承担独立职责。页面组件位于 `src/pages/`；Mock 数据位于 `src/data/mock.ts`；所有数据访问入口集中在 `src/services/api.ts`。查询提取逻辑位于 `src/lib/query.ts`。

接入真实后端时，优先替换 `api.getOverview`、`api.getRecords` 和 `api.searchRecords`，并增加详情及聚合统计接口。AI 面板目前使用本地统计与模板回复；接入模型服务后应明确展示证据、引用和不确定性。

## 本阶段验收

- 自然语言输入识别条件标签，支持拖动标签顺序、删除标签、回车提交。
- 查询解析动画完成后进入结果页，筛选、排序、图表点击和抽屉操作可用。
- 洞察面板默认展示摘要、地区、岗位、专业、届别趋势；对话按需展开且明确标注为演示分析。
- 桌面、平板、手机无页面横向溢出；移动端关系图在图面内部横向滑动。
- 生产构建通过，三页无浏览器运行错误。

## 后续阶段

1. 将 React 构建产物接到 FastAPI 的静态文件入口，替换旧 `app/static` 页面。
2. 为真实查询、筛选、记录详情、来源证据和聚合统计建立明确的 API 响应格式。
3. 在真实数据上验证空结果、OCR 待核对、加载失败和大数据量性能，再决定虚拟列表与分页策略。
4. 收到参考视频后只对比交互节奏，检查四项差异：配色、首页构图、结果架构、AI 呈现。
